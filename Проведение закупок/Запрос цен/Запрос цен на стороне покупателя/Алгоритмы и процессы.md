# Алгоритмы и процессы

Алгоритмы и процессы в [БЗ Складских документов](https://link.saby.ru/page/kbase_entity/01a9e45d-b671-4ebb-b9af-b599b21c8a4e?folderId=dae4bdb1-f75f-4687-8ae7-73a06ac65585)

## Поля торга в документе Запрос цен

Для документа «PriceMatchingOut» разработано визуальное представление «Запрос цен» для работы с множественной отправкой поставщикам. Тип документа «PriceMatchingOut» имеет набор полей в ДокументРасширение, описывающих торговую процедуру:

- предмет котировки - «Название» (string),
- дата окончания подачи заявок с указанием даты и времени - «end\_order\_date» (string),
- адрес доставки ФИАС в виде текста - «delivery\_place» (string),
- условия оплаты - «payment\_terms\_type» (string):

  - Словарь значений:

    - постоплата - "post-payment",
    - предоплата c указанием размера аванса - "prepayment",
    - по условиям контракта - "contract\_terms"
  - предоплата в процентах заполняется при выборе "prepayment" - «prepayment\_percent» (int16)
- срок поставки - «delivery\_term\_type» (string):

  - Словарь значений:

    - "immediate" - поставка сразу,
    - "by\_date" - датой,
    - "by\_days" - днями
  - при выборе "by\_date" указывается дата поставки «delivery\_term\_date» (datetime)
  - при выборе "by\_days" указывается количество дней «delivery\_term\_days» (int16)
- идентификатор торга в TenderWS (тип Int64 «tender\_id» в поле «ДокументРасширение.Параметры») ,
- идентификаторы категорий (тип массив Int64 «st\_category\_ids» в поле «ДокументРасширение.Параметры»),

  - для выбора категорий Saby Trade используем метод Category.getCategory/4
- информация по позициям котировки (название, количество, сумма, единицы измерения), базирующиеся на архитектуре складской номенклатуры

Для взаимодействия с интерфейсом данные из «ДокументРасширение.Параметры» (тип Hstore) сериализуются в поля DocExtParamsRecord.\*. В Record в поле «DocExtParamsRecord» не храним, т.к. не указать значимость этих полей в ЭДО документе для создания новой редакции ЭДО документа. Интерфейсы сохраняют данные в эти поля. Вызывают БЛ на сохранение после чего данные сериализуются в содержимое «ДокументРасширение.Параметры» на стороне логики Складов.

## Публикация запроса цен в сервис TenderWS

Документ Запрос цен можно опубликовать в сервис мониторинга Торгов. В открытой части пользователи смогут его найти и подать заявку с карточки торга.

Для публикации в регламент Запроса цен добавить суперфазу "Публикация в Saby Trade". Фаза выполняется "Автоматически".

Реализация суперфазы выполнена на C++.  Класс STPublishSPhase - наследник SPhaseBase (см. [код](https://git.sbis.ru/edo/core/-/blob/rc-25.6100/sbis-tender-sphases/implementation/super_phases/publish_tender_sphase.cpp?ref_type=heads)).

Реализуем методы класса STPublishSPhase. В методе OnCloseEvent вызываем прикладной обработчик `TenderPriceMatchingOut.ExecuteSTSuperPhase`, который переведет торг на этап "Прием заявок" и выполнит публикацию запроса цен в мониторинге торгов.

Для привязки суперфазы к документ PriceMatchingOut с визуальным представлением "Запрос цен" в метод `PriceMatchingOut.GetInfoAboutSuperPhase` добавлено локальное событие `online.pricematchingoutaddphases` на которое подписан обработчик `TenderPriceMatchingOut.AddPhases/1`. Входной параметр sphases (RecordSet) со списком суперфаз. Обработчик добавляет в него суперфазу с уникальным идентификатором:

```javascript
pp_rec = sphases.AddRow()
# идентификатор супера отправки публикации
pp_rec.ИдентификаторСуперфазы = 'ad8b81efbb9349a9bba2e07fa50f86d8'
pp_rec.Название = 'Публикация в Saby Trade'
pp_rec.Отправка = True
pp_rec.ЕстьОтветКонтрагенту = False
pp_rec.БазовыйБП = Record()
# пока не работает без роли, добавить что-нибудь
pp_rec.РольИсполнителя = None
return sphases
```

### Асинхронная работа по сохранению заявок и публикации торга

Для предотвращения "гонки" обновления в БД одной и той же записи торга (статуса торга) или заявки (статус заявки) в вызовах

- метода TenderPriceMatchingOut.Publish и TenderPriceMatchingOut.SaveChangesAfterValidate вызываются одновременно при вызове публикации, т.к. действия выполняются на обработчиках ВыполнитьДействие и Редактировать для документа, вызывающихся одновременно
- метода TenderPriceMatchingIn.SaveOfferByEmail и TenderPriceMatchingIn.Create и TenderPriceMatchingIn.SaveChanges вызываются одновременно при множественной отправке поставщикам ценовых предложений и их быстром ответе или заполнении вручную ответа самим Заказчиком.

используются рекомендательные блокировки по uuid ЭДО документа (связь торга и документа хранится в таблице tender2uuid).

## Закрытый запрос цен

Закрытый запрос цен отличается от открытого тем, что не публикуется в открытой части площадки (продукт Торги и закупки и на карточке компании), и в нем могут участвовать только те поставщики, которых пригласил покупатель. Для открытого запроса цен в регламенте используется суперфаза "Публикация в Saby Trade".

Признак закрытого торга хранится в поле extra\_data (тип jsonb) таблицы tender\_ext. Добавлен ключ  в json структуру с названием "is\_private\_participation" с типом boolean.

В сервисе Торгов (tender) и сервисе обработки фоновых задач (tender-worker) данный ключ проверяется у обрабатываемого торга, что ограничивает доступ пользователям, не имеющим отношение к торгу, и попадания в систему индексации торгов.

## Завершение приема заявок

После публикации торга через суперфазу "Публикация в Saby Trade" или при множественной отправке через супефазу "Отправка документа" торг принимает статус "Прием заявок" в сервисе TenderWS.

На документе за работу с "Приемом заявок" отвечает этап, размеченный настройкой на регламенте Запроса цен. Для этого в методе `PriceMatchingOut.PhaseSettings` добавили найстройку с id = `requestReceivingToggle` и конфигом:

```python
{
	'id': CustomPhaseSettings.REQUEST_RECEIVING_TOGGLE,
	'type': 'toggle',
	'additionalTemplateOptions': {
		'title': sbis.rk('Прием заявок в закупке'),
	},
	'mainTemplateOptions': {'text': sbis.rk('Прием заявок в закупке')},
	'resetValue': CustomPhaseToggleValues.NOT_REQUIRED,
}
```

После чего в регламенте можно будет отметить какой этап будет этапом, где принимаются заявки от поставщиков. При уходе с этого этапа торг переходит в "Работу комиссии".

Этап может завершиться 2умя способами:

1. автоматически завершиться
2. пользователь уйдет с этого этапа через ДЗЗ.

### Настройка автоматического завершения прием заявок

Срок автоматического завершения по дате/времени регулируется [полем "Приём заявок до"](https://online.sbis.ru/shared/disk/f9ea1e0c-1284-4f79-9d8d-9598bf5bccfb). Сохраняем его значение в поле "end\_order\_date" (string) в ДР.Параметры. Поле не редактируется после наступления указанного в нем времени. Поле "Приём завок до" установим в текущее после перехода на этап "рассмотрения заявок", если оно еще не наступило.

В инсталляционном регламенте на этапе "Приём заявок" указываем наступление срока [по формуле](https://saby.ru/help/auction/org/zapros_tsen/make_request_prices) и настраиваем регламент, чтобы при истечении срока выполнялся переход на следующий этап, настроенный в инсталляционном регламенте следующим.  В [сервис прикладного кода](https://git.sbis.ru/aps/applied-code-storage/-/blob/rc-25.6100/%D0%A4%D1%83%D0%BD%D0%BA%D1%86%D0%B8%D0%B8/%D0%9E%D0%B1%D1%80%D0%B0%D0%B1%D0%BE%D1%82%D1%87%D0%B8%D0%BA%D0%B8%20%D0%BD%D0%B0%20%D1%80%D0%B5%D0%B3%D0%BB%D0%B0%D0%BC%D0%B5%D0%BD%D1%82%D0%B5/%D0%9F%D0%BE%D0%BB%D1%83%D1%87%D0%B8%D1%82%D1%8C%D0%94%D0%B0%D1%82%D1%83%D0%9E%D0%BA%D0%BE%D0%BD%D1%87%D0%B0%D0%BD%D0%B8%D1%8F%D0%9F%D0%BE%D0%B4%D0%B0%D1%87%D0%B8%D0%97%D0%B0%D1%8F%D0%B2%D0%BE%D0%BA_f4f3da9c-fa22-41b1-9315-ac53406add5d.js?ref_type=heads) был добавлен метод `ПолучитьДатуОкончанияПодачиЗаявок(ДокументРасширение);` для использования в формуле. Метод вернет дату и время из поля "end\_order\_date" в ДР.Параметры.

Поддержим обновление срока документа при

1. переходе на этап "Прием заявок"
2. изменении даты "Приём заявок до" на этапе "Прием заявок"

для этого сделаем проверки:

1. в методе `TenderPriceMatchingOut.StateChanged`, обрабатывающем событие "`PriceMatchingOut.StateChanged`" проверяем есть ли прикладная опция у этапа, на который переходим
2. на изменение поля из ДР.Параметры "end\_order\_date"

обновим срок этапа через вызов `Docflow.RecalcDeadline/1`, передав идентификатор документа.

При вызове этого метода возьмется значение из формулы, описанной на этапе в регламенте, и поле ДокументРасширение.Срок рассчитается по ней.

Откат фазы на этапе, помеченным "Прием заявок" запрещен, т.к. смена состояния связанного торга не предусмотрена при откате и дата окончания подачи заявок уже зафиксирована ([ошибка](https://online.sbis.ru/opendoc.html?guid=66f04209-5326-4ea2-977f-8e38e5aa17f7&client=3))

## Сбор ценовых предложений с поставщиков

Покупатель собирает цены с Поставщиков через

- отправку «Запроса цен» Поставщикам, которые подключены к ЭДО,
- отправку «Запрос цен» Поставщикам, у которых есть email
- через прямой контакт с поставщиком и вводом вручную ценовых предложений за Поставщика.
- через опубликованный Торг, по которому Поставщик подает «Заявку на запрос цен»

### Добавление поставщиков в Запрос цен

Для сбора цен Покупатель добавляет Поставщиков в Запрос цен.

Отображение реестра поставщиков в мастер-панели, сохранение поставщика и контактных данных описано в [БЗ Складских документов](https://link.saby.ru/page/kbase_entity/bba4c8d3-45c6-4dbd-aeab-e0edee56dfe9?folderId=dae4bdb1-f75f-4687-8ae7-73a06ac65585#toc_ac2ed949-7a64-4048-a27c-d3a27d12f545).

При создании документа Запрос цен добавляем поставщиков, которым хотим отправить приглашение по ЭДО или email, используя объект TenderParticipantEdo, состоящий из crud методов. Добавление выполняется в таблицу result. В сервисе online у контрагентов есть уникальный идентификатор для каждой схемы - @Лицо. На документе он должен быть записан в поле Документ.Лицо1. При вызове метода TenderParticipantEdo.UpdateParticipant по Лицо1 получаем информацию о контрагенте с помощью метода ContractorReader.Get и проводим валидацию (есть ли у контрагента ИНН и не отключил ли принудительно ЭДО). Дальше вызываем метод TenderParticipant.UpdateParticipant сервиса tender, куда передаем реквизиты организации (ИНН, КПП, НазваниеПолное, ИдентификаторСПП, Лицо1). С помощью класса Contragent модуля TenderApi, сопоставляем/создаем по реквизитам организацию из таблицы participant и сохраняем заявку с переданной информацией в таблицу result. Лицо1 сохраняем в result.extra\_info, чтобы в будущем использовать для сопоставления.

### Множественная отправка Поставщикам

Алгоритм отправки по ЭДО, e-mail и в мессенджеры описан [в БЗ Складских документов](https://link.saby.ru/page/kbase_entity/bba4c8d3-45c6-4dbd-aeab-e0edee56dfe9?folderId=dae4bdb1-f75f-4687-8ae7-73a06ac65585#toc_b22f2040-b36c-493e-ba34-928e8ce25db1).

Суперфаза ЭДО "Отправка документа" имеет следующие настройки (в [БЗ Складских документов](https://link.saby.ru/page/kbase_entity/bba4c8d3-45c6-4dbd-aeab-e0edee56dfe9?folderId=dae4bdb1-f75f-4687-8ae7-73a06ac65585#toc_e2fd2d9c-22d8-409c-a79d-3b02ce66b6a4))

- для множественной отправки установлена роль получателя "Поставщик". Указываем механизму отправки ЭДО через конкретный метод БЛ каким получателям делать отправку через переопределение метода (будет дополнена информация по методу по итогу проекта [https://online.sbis.ru/opendoc.html?guid=0084c8fc-33ef-466e-927b-78948e10d921&client=3](https://online.sbis.ru/opendoc.html?guid=0084c8fc-33ef-466e-927b-78948e10d921&client=3))
- разрешаем проходить суперфазу отправки без указания получателей через указание флага PassThroughIfNoReceiver=true в конфигурации фазы "Отправка документа". Допустимо отправить запрос цен без получателей, т.к. заявки можно получить через поиск закупок в Saby Trade или сделать отправку конкретным получателям после.

#### Отправка Запроса цен

При отправке запроса цен c поставщиками подготовка информации о контрагентах (поле Receivers со списком Лицо1. кому прошла отправка) происходит в методе TenderPriceMatchingOut.AfterPhaseExecuted. В сервисе tender сопоставляем по полученным Лицо1 заявки и обновляем им статус result.invite = 1 и проставляем флаг result.extra\_info-\>edo\_transfer = true.  Требуется, чтобы на доотправке трансфер шел только по email, по ЭДО возникнет ошибка, потому что этап отправки уже выполнился.

Торг в сервисе TenderWS переходит в статус "Прием заявок", даже если он не публиковался в Saby Trade и не показывается в публичном поиске.

#### Работа с заявкой по ЭДО

При поступлении заявки в аккаунт поставщика вызывается метод TenderPriceMatchingIn.Create, где по реквизитам организации происходит сопоставление записи, у которой в дальнейшем обновляем статус заявки на черновик result.invite = -1.

При подаче result.invite = 2 или отклонении result.invite = 4 заявки так же по реквизитам сопоставляем запись в базе и обновляем все переданные поля, записываем в result.extra\_info тип отправки заявки send\_type - edo.

#### Работа с заявкой по email

Перед отправкой письма происходит генерация ссылки на форму svrd в методе [get\_link](https://git.sbis.ru/edo/core/-/blob/rc-22.1100/www/service/%D0%9C%D0%BE%D0%B4%D1%83%D0%BB%D0%B8/%D0%94%D0%BE%D0%BA%D1%83%D0%BC%D0%B5%D0%BD%D1%82%D0%BE%D0%BE%D0%B1%D0%BE%D1%80%D0%BE%D1%82/email_order.py) , где в base64 кодируем реквизиты организации и Лицо1 поставщика.

При открытии формы, вызывается метод TenderParticipant.GetParticipantInfo, в котором происходит сопоставление заявки по Лицо1 и возвращаем информацию о поставщике.

При ответе на заявку, сохранение информации в сервисе торгов происходит в методе TenderPriceMatchingIn.SaveOfferByEmail, сопоставление происходит по полю Лицо1. В поле result.extra\_info записываем send\_type - email.

#### Статусы заявок на участие

Заявки на участие могут иметь следующие состояния в поле result.invite

- 0 - Черновик, созданный организатором торга
- -2 - Статус участника, который не получил приглашения, но сам нашёл торг и подал заявку
- -1 - Черновик, созданный участником торга
- 1 - приглашение отправлено по email организации или организация подключена к СБИС
- 2  - заявка отправлена участником
- 3 - заявка введена покупателем
- 4 - поставщик отказался от участия

## Выбор победителя

Для Запроса цен для добавления этапа с выбором победителя через метод `PriceMatchingOut.PhaseSettings` внедряем найстройку с id = winnerChoiceToggle и конфигом:

```python
{
	'id': CustomPhaseSettings.WINNER_CHOICE_TOGGLE,
	'type': 'toggle',
	'additionalTemplateOptions': {
		'title': sbis.rk('Выбор победителя в закупке'),
	},
	'mainTemplateOptions': {'text': sbis.rk('Выбор победителя в закупке')},
	'resetValue': CustomPhaseToggleValues.NOT_REQUIRED,
}
```

Для выбора победителя размечаем этап в регламенте признаком "Выбор победителя в закупке", который можно указать на любом из этапов в регламенте документа.

На размеченном этапе в ДЗЗ показываем список участников, где выберем одного или нескольких.

### Смена статуса торга при выходе с этапа "выбора победителя"

При выполнении перехода с этапа отмеченного опцией "Выбор победителя в закупке" анализируется тип перехода для установки статуса связанного торга на площадке Saby Trade с Запросом цен:

- нейтральный завершающий переход и положительный переход - переводим торг в статус "рассмотрение заявок"
- отрицательный переход - переводим торг в отменен, игнорируя указанных поставщиков или сбрасывая поставщиков, если они были выбраны победителями.

Переход "Переназначить" не влияет на статус торга.

Откат фазы на этапе, помеченным "выбором победителя" запрещен, чтобы на источнике не происходило переключения статуса на "Работа комиссии"

### Лучшие предложения

Алгоритм определения:

1. Самое выгодное предложение по позиции
2. Поставщик прислал ответ по большему количеству позиций
3. Самое выгодное предложение по всем позициям

На документе Запрос цен есть кнопка "Лучшие предложения" в правом тулбаре. По ней покажем отчёт с выгодными предложениями среди всех поставщиков. Выбор лучших позиций осуществляется на основании самого выгодного предложения по позиции.

Используется метод **TenderPriceMatchingOut.GetBestOffers/1**,принимающий на вход Record с полем tender\_id – id торга.

### Цена при нескольких победителях

Цена определяется в соответствии с сортировкой по приоритету:

1. наибольшее количество позиций по которым предложены цены
2. наименьшая предложенная суммарная цена по всем позициям

Цена показывается в

- реестрах документов
- в реестре "Закупки"
- в построении и детализации виджета "Закупали"

После прохождения этапа, помеченного признаком "Выбор победителя в закупке" предложение победителя фиксируется и для его предложения в поле result.extra\_info-\>\>"prefered\_winner" проставится значение "1".

# База данных

Сервис TenderWSRU хранит торговую проекцию документа: торг, лот и позиции, участников, заявки и ценовые предложения. Документ и его номенклатура остаются в базе online. Связь - по идентификатору документа.

## Схема сущностей

![Схема связей между таблицами](База%20данных.assets/Схема%20данных.png)

| Таблица | Что хранит | Применение в Запросе цен |
| --- | --- | --- |
| `tender` | Торг: предмет закупки, статус, сроки | Сама закупка, созданная по документу; её статус показывается в карточке и реестрах |
| `tender2uuid` | Связь торга с исходящим документом `QuoteRequestOut` | Найти торг по документу и не создать дубль при повторной публикации |
| `tender_ext` | Расширение торга: папка, секция, признак закрытого запроса цен | Закрытая закупка не попадает в открытый поиск, торг размещается в нужном разделе |
| `lot` | Лот закупки | В лот переносятся позиции документа; в Запросе цен у торга один лот |
| `lotitem` | Позиции лота: номенклатура, количество | Состав закупки, с которым сравниваются предложения поставщиков |
| `participant` | Контрагент-поставщик | Участник приглашения и заявки; сопоставляется по ИНН |
| `result` | Заявка поставщика: комментарии, дата получения, канал, признак ЭДО, победитель | Хранит ответ по любому каналу и итог выбора; основа реестра заявок и лучших предложений |
| `resultitem` | Позиции заявки: цена за единицу, количество | Ценовые предложения по позициям, из которых строятся лучшие предложения |
| `result2uuid` | Связь заявки с входящим документом `QuoteRequestIn` | Найти заявку по входящему документу поставщика |

Поля и типы таблиц - в автодокументации TenderWSRU: [структура базы данных сервиса](https://wi.saby.ru/page/autodoc-database/services/Service/b7c44351-9476-4b60-b352-a3d07f106a1b%2F7e9389a3-05f8-49a9-8420-b4516baac96d?v=26.5100).

## Типовые выборки

1. **Связанный торг по документу.** `tender2uuid` по `uuid` документа и `doc_type = 'quote_request_out'`, далее `tender` по `tenderid`.

2. **Участники закупки.** `result` по `tenderid`, `participant` по `participantid`. Количество и сумму позиций получаем агрегацией `resultitem` по `resultid`.

3. **Предложение поставщика.** `result` по `"@result"`: комментарий поставщика, комментарий покупателя, дата получения, канал и признак ЭДО из `extra_info`.

4. **Цены по позициям.** `resultitem` по `resultid`: цена за единицу, количество, номер позиции.

5. **Лучшие предложения.** `result` join `resultitem` по `resultid`. Сортировка по признаку `prefered_winner`, затем по сумме и количеству позиций. Нумерация `row_number` по `position_number`, отбор `row_number = 1`.

## Индексы

| Индекс | Назначение | Выборки |
| --- | --- | --- |
| `tender2uuid(uuid)` | Связанный торг по документу | 1 |
| `result(tenderid)` | Участники и лучшие предложения | 2, 5 |
| `result("@result")` | Заявка по идентификатору | 3 |
| `participant(sppid)` | Данные организации | 2 |
| `resultitem(resultid)` | Позиции заявки | 2, 4, 5 |
| `lot(tenderid, lotnumber)` | Лот по номеру | 5 |
| `lotitem(lotid, lotitemnumber, id)` | Позиция лота по номеру | 5 |

# База данных

Сервис торгов хранит торговую проекцию документа: торг, лот и позиции, участников, заявки и ценовые предложения. Документ и его номенклатура остаются в базе online. Связь - по идентификатору документа.

## Схема данных

| Таблица | Назначение | Связь |
| --- | --- | --- |
| `tender` | Торг | - |
| `tender2uuid` | Связь торга с исходящим документом `QuoteRequestOut` | `tenderid` -> `tender.id` |
| `tender_ext` | Расширение торга: папки, секция, закрытый запрос цен | `tender_id` -> `tender.id` |
| `lot` | Лот закупки | `tenderid` -> `tender.id` |
| `lotitem` | Позиции лота | `lotid` -> `lot.id` |
| `participant` | Контрагент | - |
| `result` | Заявка участника | `tenderid` -> `tender.id`, `participantid` -> `participant.id` |
| `resultitem` | Позиции заявки | `resultid` -> `result."@result"` |
| `result2uuid` | Связь заявки с входящим документом `QuoteRequestIn` | `resultid` -> `result."@result"` |

Связи между таблицами:

- торг 1:N лоты, лот 1:N позиции;
- торг 1:N заявки, заявка 1:N позиции;
- заявка ссылается на лот по `lotnumber`;
- позиция заявки ссылается на позицию лота по `position_number` и `lotitemnumber`;
- участник заявки - `participant.id`.

## Ключевые поля

### tender

| Поле | Тип | Назначение |
| --- | --- | --- |
| `id` | INT64 | Идентификатор торга |
| `uuid` | UUID | UUID торга |
| `tendername` | STRING | Предмет закупки |
| `stateaggid` | INT64 | Агрегированный статус торга |
| `endorderdate` | DATE | Срок окончания подачи заявок |
| `supplierid` | INT64 | Победитель |
| `winprice` | MONEY | Цена победителя |
| `is_draft` | BOOLEAN | Черновик |
| `created_at`, `modified_at` | DATETIME | Создание и изменение |

### tender2uuid

| Поле | Тип | Назначение |
| --- | --- | --- |
| `uuid` | UUID | Идентификатор исходящего документа |
| `tenderid` | INT64 | Торг |
| `clientid` | INTEGER | Клиент |
| `doc_type` | STRING | Тип документа, для запроса цен - `quote_request_out` |
| `creation_datetime` | DATETIME | Дата связи |
| `extra_data` | HASHTABLE | Дополнительные данные связи |

### tender_ext

| Поле | Тип | Назначение |
| --- | --- | --- |
| `tender_id` | INT64 | Торг |
| `extra_data` | HASHTABLE | Дополнительные данные, в том числе `is_private_participation` для закрытого запроса цен |
| `section_id` | INT16 | Секция |
| `folder_ids` | INT8[] | Папки торга |

| Поле | Тип | Назначение |
| --- | --- | --- |
| `id` | INT64 | Идентификатор лота |
| `tenderid` | INT64 | Торг |
| `lotnumber` | INT64 | Номер лота |
| `name` | STRING | Наименование лота |

### lotitem

| Поле | Тип | Назначение |
| --- | --- | --- |
| `id` | INT64 | Идентификатор позиции |
| `lotid` | INT64 | Лот |
| `lotitemnumber` | INT64 | Номер позиции в лоте |
| `name` | STRING | Наименование позиции |
| `quantity` | DOUBLE | Количество |
| `price` | MONEY | Цена за единицу |
| `okei_name`, `okei_code` | STRING | Единица измерения |
| `nomenclature_id` | INT64 | Номенклатура |
| `extra_info` | STRING, JSON | Данные из документа: `nom_number`, `comment`, `НоменклатураДокументаРасш.ЕИУ`, `КоличествоПоУпаковке` |

### participant

| Поле | Тип | Назначение |
| --- | --- | --- |
| `id` | INT64 | Идентификатор участника |
| `name`, `brief` | STRING | Полное и краткое наименование |
| `inn`, `kpp` | STRING | Реквизиты |
| `email`, `phone`, `contactname` | STRING | Контакты |
| `sppid`, `spp_uuid` | INT64, UUID | Связь со СПП |

### result

| Поле | Тип | Назначение |
| --- | --- | --- |
| `tenderid` | INT64 | Торг |
| `participantid` | INT64 | Участник |
| `lotnumber` | INT64 | Лот |
| `price`, `pricerub` | MONEY | Сумма заявки |
| `admitted` | BOOLEAN | Заявка допущена |
| `apprating` | INT64 | Рейтинг заявки, 1 - победитель |
| `appdate` | DATETIME | Дата подачи |
| `invite` | INTEGER | Статус приглашения или заявки |
| `journalnumber` | STRING | Номер заявки |
| `email`, `phone`, `contactname` | STRING | Контакты |
| `comment`, `reject_reason` | STRING | Комментарий и причина отказа |
| `extra_info` | HASHTABLE | `customer_amount`, `customer_comment`, `received_datetime`, `send_type`, `edo_transfer`, `prefered_winner`, `change_datetime`, `Лицо1` |

Ключ заявки - `tenderid`, `journalnumber`, `lotnumber`. Поле `@result` - идентификатор заявки на площадке; по нему `resultitem.resultid` и `result2uuid.resultid` находят заявку.

| `unit_price` | MONEY | Цена за единицу |

| `extra_data` | HASHTABLE | `ext_nom_number`, `ext_nom_name`, `nom_number`, `comment`, `price_base`, `count_base` |

## Статусы

### Статус торга

| `tender.stateaggid` | Статус |
| --- | --- |
| 1 | Черновик |
| 2 | Приём заявок |
| 3 | Рассмотрение заявок |
| 4 | Подведение итогов |
| 5 | Отменён |
| 42 | Не состоялся |

### Статус заявки

| `result.invite` | Статус |
| --- | --- |
| 0 | Черновик организатора |
| -2 | Нашёл сам |
| -1 | Черновик участника |
| 1 | Приглашение отправлено |
| 2 | Заявка отправлена |
| 3 | Заявка введена покупателем |
| 4 | Отказ |

## Типовые выборки

1. **Связанный торг по документу.** `tender2uuid` по `uuid` документа и `doc_type = 'quote_request_out'`, далее `tender` по `tenderid`.
2. **Участники закупки.** `result` по `tenderid`, `participant` по `participantid`. Количество и сумму позиций получаем агрегацией `resultitem` по `resultid`.
3. **Предложение поставщика.** `result` по `"@result"`: комментарий поставщика, комментарий покупателя, дата получения, канал и признак ЭДО из `extra_info`.
4. **Цены по позициям.** `resultitem` по `resultid`: цена за единицу, количество, номер позиции.
5. **Лучшие предложения.** `result` join `resultitem` по `resultid`. Сортировка по признаку `prefered_winner`, затем по сумме и количеству позиций. Нумерация `row_number` по `position_number`, отбор `row_number = 1`.

## Индексы

| Индекс | Назначение |
| --- | --- |
| `tender2uuid(uuid)` | Связанный торг по документу |
| `tender2uuid(tenderid)` | Документы торга |
| `result(tenderid)` | Участники и лучшие предложения |
| `participant(sppid)` | Данные организации |
| `resultitem(resultid)` | Позиции заявки |
| `lot(tenderid, lotnumber)` | Лот по номеру |
| `lotitem(lotid, lotitemnumber, id)` | Позиция лота по номеру |
| `result2uuid(uuid)`, `result2uuid(resultid)` | Связь заявки с входящим документом |

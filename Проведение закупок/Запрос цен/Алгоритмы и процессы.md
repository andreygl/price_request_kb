# Алгоритмы и процессы

Закупка в торгах проходит по сценарию: проекция документа → приём заявок → завершение приёма → выбор победителя → итоги. Публикация в Saby Trade зависит от регламента. Если в нём есть прохождение "Публикация в Saby Trade", торг показывается в мониторинге закупок, поставщики находят его через поиск и подают заявки. Если прохождения нет, участвуют только приглашённые поставщики. Покупатель и поставщик участвуют в одном процессе с разных сторон; их действия описаны внутри шагов.

Поля документа, номенклатура, контакты, вложения, каналы доставки и интерфейс карточки описаны в [основной технической документации по Запросу цен](https://link.saby.ru/page/kbase_entity/01a9e45d-b671-4ebb-b9af-b599b21c8a4e?folderId=91b04551-1630-4733-a720-ba4ffad14655). Здесь - логика сервиса торгов.

## 1. Проекция документа в торг

При создании черновика документа в сервисе торгов создаётся черновик торга. Связь хранится в `tender2uuid`: `uuid` - идентификатор документа, `tenderid` - торг, `doc_type` - `quote_request_out`.

Лот и позиции формируются при публикации. Данные документа переносятся в `lot` и `lotitem`:

| Поле документа | Поле торга |
| --- | --- |
| `Номенклатура.Наименование` | `lotitem.name` |
| `ВходящееНаименование.Наименование`, если нет `Номенклатура.Наименование` | `lotitem.name` |
| `КоличествоПоУпаковке`, иначе `Количество` | `lotitem.quantity` |
| `ЦенаПоУпаковке`, иначе `Цена` | `lotitem.price` |
| `Номенклатура` | `lotitem.nomenclature_id` |
| `НазваниеЕИ` | `lotitem.okei_name` |
| `НоменклатураДокументаРасш.Комментарий` | `lotitem.addinfo` |
| `Номенклатура.НомНомер` | `lotitem.extra_info->nom_number` |
| `НоменклатураДокументаРасш.Комментарий` | `lotitem.extra_info->comment` |
| `НоменклатураДокументаРасш.ЕИУ` | `lotitem.extra_info->НоменклатураДокументаРасш.ЕИУ` |
| `КоличествоПоУпаковке` | `lotitem.extra_info->КоличествоПоУпаковке` |

Идентификатор торга хранится в параметрах документа.

Сохранение заявок и публикация выполняются асинхронно. Чтобы не обновлять одну запись торга или заявки одновременно, используются рекомендательные блокировки по uuid документа. Это нужно, когда одновременно срабатывают публикация и сохранение, а также множественная отправка и быстрый ответ поставщика.

## 2. Публикация и статусы

Торг создаётся вместе с документом и до публикации остаётся черновиком. Публикация выводит его в реестр торгов Saby Trade, чтобы поставщики нашли закупку через поиск, и переводит в приём заявок.

Публикацию выполняет прикладная суперфаза `STPublishSPhase` из EDO-репозитория `sbis-tender-sphases`. В `OnCloseEvent` она асинхронно вызывает `ExecuteSTSuperPhase` у объекта торгов, который переводит торг в "Приём заявок" и размещает закупку в мониторинге торгов. Суперфаза добавляется в документ по событию `online.quoterequestoutaddphases` обработчиком `TenderQuoteRequestOut.AddPhases`.

Исходный код суперфазы: [sbis-tender-sphases](https://git.sbis.ru/edo/core/-/tree/HEAD/sbis-tender-sphases). Идентификатор суперфазы - `ad8b81efbb9349a9bba2e07fa50f86d8`; в ленте событие называется "Опубликовано в Saby Trade".

| Статус торга | Что означает |
| --- | --- |
| Черновик | Торг создан, на площадке не виден |
| Приём заявок | Торг опубликован, поставщики могут подавать заявки |
| Рассмотрение заявок | Приём завершён, покупатель работает с предложениями |
| Завершён | Победитель выбран, итоги зафиксированы |
| Отменён | Закупка отменена |
| Не состоялся | Закупка не собрала участников или заявок |

**Закрытый запрос цен.** Признак закрытого торга хранится в `tender_ext.extra_data` под ключом `is_private_participation` и проверяется в сервисе торгов и tender-worker. Проверка не даёт закрытому торгу попасть в открытый поиск и индексацию и ограничивает доступ пользователям, не связанным с торгом.

При множественной отправке документа торг переходит в приём заявок, но в открытом поиске не показывается.

## 3. Приём заявок

### Добавление поставщика

При создании документа поставщиков добавляют в торг объектом `TenderParticipantEdo`. По `Лицо1` из документа получают контрагента, проверяют ИНН и признак ЭДО, затем через `TenderParticipant.UpdateParticipant` сопоставляют или создают организацию в `participant` и сохраняют заявку в `result`. `Лицо1` сохраняется в `result.extra_info` для последующего сопоставления.

### Каналы

| Канал | Что происходит в торгах |
| --- | --- |
| ЭДО | `TenderQuoteRequestIn.Create` создаёт заявку, при отправке ставится `result.invite = 2` или `4`, `send_type = edo`, `edo_transfer = true` |
| Email и СВРД | `TenderQuoteRequestIn.SaveOfferByEmail` сохраняет ответ, `send_type = email`; аккаунт поставщика не нужен |
| Мессенджер | Поставщик переходит по приглашению и подаёт заявку |
| Поиск торгов | Поставщик находит опубликованный торг сам, `result.invite = -2` |
| Ручной ввод | Покупатель вводит цену за поставщика, `result.invite = 3` |

Каждый канал приводит к одной заявке в `result` и позициям в `resultitem`.

### Статусы заявки

| Код | Статус | Что означает |
| --- | --- | --- |
| 0 | Черновик организатора | Заявку создал покупатель |
| -2 | Нашёл сам | Поставщик не получил приглашение, но нашёл торг и подал заявку |
| -1 | Черновик участника | Поставщик начал оформлять заявку |
| 1 | Приглашение отправлено | Приглашение ушло по email или поставщик подключён к ЭДО |
| 2 | Заявка отправлена | Поставщик отправил предложение |
| 3 | Заявка введена покупателем | Цены ввёл покупатель за поставщика |
| 4 | Отказ | Поставщик отказался от участия |

### Ручной ввод цены

Если поставщик не ответил, покупатель вводит цены за него. Сумма сохраняется в `result.extra_info->customer_amount`, комментарий - в `customer_comment`, дата изменения - в `change_datetime`. Если поставщик позже пришлёт своё предложение, оно перезапишет ручной ввод.

## 4. Завершение приёма заявок

Приём завершается двумя способами:

1. автоматически по сроку "Приём заявок до";
2. переходом покупателя с этапа, помеченного настройкой "Приём заявок в закупке".

Настройка этапа задаётся в `QuoteRequestOut.PhaseSettings` под идентификатором `requestReceivingToggle`. Срок хранится в параметрах документа в поле `end_order_date` и не редактируется после наступления. При переходе на этап приёма и при изменении срока на этом этапе срок пересчитывается через `Docflow.RecalcDeadline`. После завершения приёма торг переходит в рассмотрение заявок.

Откат фазы с этапа приёма запрещён: статус связанного торга и зафиксированный срок уже изменились.

## 5. Выбор победителя

Победитель выбирается на этапе, помеченном настройкой "Выбор победителя в закупке". Настройка задаётся в `QuoteRequestOut.PhaseSettings` под идентификатором `winnerChoiceToggle`.

На этапе покупатель видит список участников и выбирает одного или нескольких. Список получают методом `TenderParticipantEdo.ListParticipant`. Идентификаторы победителей передаются в `winner_org_ids` и обрабатываются `TenderQuoteRequestOut.WinnersSelected`.

Правила:

- выбранный поставщик получает `result.admitted = true` и `result.apprating = 1`;
- если победителей несколько, лучшее предложение выбирается по приоритету: больше позиций с ценами, затем меньшая суммарная цена;
- после прохождения этапа в заявке победителя выставляется `result.extra_info->prefered_winner = 1`.

### Смена статуса торга при выходе с этапа

- нейтральный завершающий и положительный переходы переводят торг в рассмотрение заявок;
- отрицательный переход отменяет торг и сбрасывает выбранных победителей;
- переход "Переназначить" статус торга не меняет.

Откат фазы с этапа выбора победителя запрещён.

## 6. Лучшие предложения и итоговая цена

Отчёт "Лучшие предложения" показывает выгодные предложения среди всех поставщиков. По каждой позиции выбирается предложение с минимальной ценой; при равенстве - предложение поставщика, ответившего по большему количеству позиций; затем - лучшее предложение по всем позициям. Отчёт строит `TenderQuoteRequestOut.GetBestOffers`.

Итоговая цена при нескольких победителях определяется по приоритету: больше позиций с ценами, затем меньшая суммарная цена. Цена показывается в реестрах документов, в реестре "Закупаем" и в виджете "Закупали".

## 7. Якоря в коде

| Процесс | Объект ORX | Точка входа |
| --- | --- | --- |
| Создание, удаление, фазы торга | `TenderQuoteRequestOut` | события `online.quoterequestout*` |
| Ответ поставщика по ЭДО | `TenderQuoteRequestIn` | события `online.quoterequestin*` |
| Подача заявки из карточки торга | `TenderParticipantOffer` | `TenderParticipantOffer.Create` |
| Выбор победителя | `TenderQuoteRequestOut` | `TenderQuoteRequestOut.WinnersSelected` |
| Лучшие предложения | `TenderQuoteRequestOut` | `TenderQuoteRequestOut.GetBestOffers` |

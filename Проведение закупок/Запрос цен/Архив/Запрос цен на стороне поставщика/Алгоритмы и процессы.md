## **Взаимодействие с поставщиком с подключенным ЭДО**

![](Алгоритмы%20и%20процессы.assets/r1.png)

Рисунок 1. Взаимодействие с поставщиком, подключенным по ЭДО

Для взаимодействия между Покупателем и Поставщиком используются два существующих типа ЭДО

документа:

- «PriceMatchingOut» - документ создаётся в схеме Покупателя и показывается в реестре «Закупки / Заказы» на вкладке «Запросы цен»,
- «PriceMatchingIn» - документ создаётся в схеме Поставщика и показывается в реестре «Продажи / Заказы» на вкладке «Запросы цен».

Эти типы реализуют функционал складского документа в части работы с номенклатурными позициями в схеме клиента. Документ передаёт запрос цен по номенклатурным позициям от Покупателя к Поставщику.

### **Работа с документом PriceMatchingIn при доставке по ЭДО**

Для документа «PriceMatchingIn» разработан регламент «Запрос цен». У регламента «Запрос цен» создано [визуальное представление документа](https://wi.sbis.ru/doc/edo/main-editing-doc/doc-view/) с именем «Запрос цен».

Тип документа «PriceMatchingIn» характеризует ценовое предложение Поставщика и хранит данные:

- комментарий,
- идентификатор документа ЭДО (поле «ИдентификаторДокумента»), который совпадает с guid’ом отправленного документа PriceMatchingOut (так реализована отправка в ДО),
- информация по позициям котировки (название, количество, сумма, единицы измерения), базирующиеся на архитектуре складской номенклатуры. Ниже приведено описание хранимых полей (метод prepare\_nomenclature\_item)

При отправке ценового предложения из схемы Поставщика информация по складской номенклатуре сохраняется в поля таблицы resultitem и поле расширение resultitem.extra\_data (тип jsonb):

Информация в tender по заявке на участие поступает после перехода на завершающий положительный или отрицательный переход по регламенту, см. Рисунок 1 . Сам документ PriceMatchingIn не доставляется в схему Покупателя в соответствии с настроенным инсталляционным регламентом.

На локальное событие в online "online.pricematchinginbeforephaseexecuted" выполняется валидация возможности подачи заявки пока не окончен срок подачи.

При отправке ценового предложения Поставщиком, подключенным к ЭДО в СБИС, срабатывает событие **online.pricematchinginafterphaseexecuted**. Обработчик сохраняет данные по ценовым позициям как описано выше в таблице в сервис TenderWS, заявка в таблице result принимает статус «Отправлена».

После чего у Покупателя в реестре поставщиков котировки будет доступно предложение от данного Поставщика. Форма просмотра информации по ценовому предложению Поставщика строится на основании данных из сервиса TenderWS и на основе компонентов сервиса Торгов.

При множественной отправке по ЭДО каждому получателю будет отправлен XML-документ на его абонентский ящик на сервисе «Оператора связи», если такого нет, то он будет создан. В процессе отправки формируется письмо, указанное в настройках ЭДО документа Запрос цен, генерируется ссылка на сервис svrd. В ссылку добавляется идентификатор сеанса обмена, ИНН и КПП получателя. Когда получатель заходит по ссылке, то на основании идентификатора сеанса обмена из сервиса «Оператора связи» подтягиваются данные документа запроса цен и показываются на форме.

По email каждому из получателей реализован механизм подмены якорей в шаблоне письма на основе словаря с данными через поле Anchor в методе **DocumentEmail.SendEmail**. В связи с этим форма отправки для каждого из получателей может содержать уникальные данные (в случае текущего шаблона письма - это название приглашаемой организации к участию в письме).

## **Поставщик подаёт заявку через поиск в торгах и закупках**

Для проброса данных в сервис Торгов при работе со складским документом используются [сервисные события в рамках одного рабочего процесса](https://wi.sbis.ru/doc/platform/developmentapl/service-development/services-cooperation/subscription-to-events-in-the-cloud/single-workflow/). Методы складского документа «PriceMatchingOut» на CRUD-операции, на переходы по фазам регламента, при работе с номенклатурой, вложениями бросают события в online. Обработчики от "Торгов" в online срабатывают, дополняют данные по документу и направляют их в сервис tender.

В tender эти данные используются для

- отображения процедуры в мониторинге торгов и возможности подачи заявки через сервис «Торги и закупки»,
- ведения статистики участий и проведения торгов.

Через сервис «Торгов и закупок» Поставщик находит опубликованный Запрос цен. Нажимает на нём кнопку «Участвовать».

![](Алгоритмы%20и%20процессы.assets/r3.png)

Рисунок 4. Поставщик сам подаёт заявку

[Форма подачи заявки](http://axure.tensor.ru/sabytrade/#g=1&p=%D1%82%D0%BE%D1%80%D0%B3) – складская, но имеет свое визуальное представление "Запрос цен", т.к. содержит вкладку «Котировка» с информацией по Торгу из сервиса TenderWS. Вызывается метод tender **TenderParticipantOffer.Create/1**,  где передаётся торг в ключе “tender\_id”.

Создаётся документ «Запрос цен» и формируются наименования от Покупателя через вызов **PriceMatchingWnIn.NomCreateWithSaveBatch**. В TenderWS создаётся заявка на участие со статусом «Черновик».

Описание процесса в [БЗ скадских документов](https://link.saby.ru/page/kbase_entity/bba4c8d3-45c6-4dbd-aeab-e0edee56dfe9?folderId=dae4bdb1-f75f-4687-8ae7-73a06ac65585#toc_7251300f-0405-4cc5-ba03-fa846f2eb46a).

## **Покупатель сам вводит цену за поставщика**

Если поставщик не прислал ценовое предложение, то сам покупатель может ввести за него ценовые предложения. Вызывается метод **TenderParticipantOffer.CreateManualOffer/1**,  где передаётся идентификатор заявки в ключе “result\_id”. Данные по заявке полностью копируются из лота. Организатор правит только ценовое предложение.

Цена указанная покупателем, хранится в поле result.ext\_data-\>customer\_amount и дата/время указания цены result.ext\_data-\>change\_datetime. Если поставщик прислал её сам, то цена поставщика сохраняется в result.price, а цена, указанная покупателем сбрасывается. На интерфейсе указывается сумма указанная покупателем, при этом подсвечивается, что есть цена у поставщика.

Все поля, которые были в таблице lotitem и lotitem.extra\_data доступны для последующего заключения договора.
